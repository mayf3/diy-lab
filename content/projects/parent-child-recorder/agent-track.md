**D（目标）**：规划小型可佩戴鱼眼相机，考虑挂脖等方式，尽可能完整记录亲子教学互动；与口喷神器分别设计和制作；当前阶段仅整理设计条件，具体选型与报价属于后续阶段。

**受众约束**：希望记录亲子教学过程的家长，不预设拥有相机模组、打印机或电子制作工具。

**禁止误解为目标**：

- 将相机与口喷神器合并制作，或预设二者共用硬件、采购和实施顺序
- 将鱼眼镜头视为已经实现无遗漏记录的证明
- 将需求登记视为已完成硬件选型、采购或实拍验收
- 向公开仓库提交可识别的儿童影像、声音或私人会话
- 在本次需求登记阶段直接开展硬件选型、报价或采购；这些属于设计条件明确后的后续阶段

1. 读取当前用户的设备/预算/技能约束；**只问缺少且会改变实际方案的信息**。不要假设用户有 P1S 或 Mac。
2. 自行获取官方上游、工程文件、BOM 和适用的软件版本；对上游每一个关键型号/版本记录来源、时间、可验证范围。
3. 可用工具能读到的页面、CAD/模型、硬件规格和报价，**自己调用工具检查**，不要把“去看源码”转交给用户。工具受限时请求最低限度文件，不编造已检查。
4. 报告每一关的状态：planned / observed / failed / blocked，输出证据位置、影响以及下一步。**模拟 ≠ 实物、读取 ≠ 验收、建议 ≠ 批准付款。**
5. 对付款、首次通电、不可逆烧录/焊接、儿童使用和安全相关动作，要求真实用户决定或现场证据；不绕过安全检查。

## A/V/R（动作、证据、依赖与阻断）

### A01 · 整理记录需求与验收边界

- **执行者**：agent；**依赖**：无；**状态**：planned
- **目的**：形成已确认需求、待设计参数和后续验证方法的草案
- **Agent 必做**：

- 从已登记的小型可佩戴硬件、鱼眼相机及亲子教学记录目标继续整理，不要求用户重复确认这些需求
- 将佩戴位置、取景覆盖、收音、录制时长、续航、存储和预算保持为待定，说明各项会影响什么设计
- 提出可观察的录制和回看验收方法，仅对新增且会改变方案的取舍请求用户判断
- 保持相机与口喷神器两个独立项目的边界，不生成未经核实的型号、价格或采购结论

- **必须由人完成/提供**：

本关不要求你操作。

- **应交付**：设计条件草案；取景、录制与回看的待验证项
- **V 证据**：human-confirmation，草案保留已确认方向并明确待定项；新增关键取舍在设计阶段确认，未执行的实拍保持待验证，当前 planned
- **R 遇阻条件**：缺少参数时记录未知及其影响，继续整理已有需求，不把未定参数写成已确认规格

# 亲子教学随身记录器｜Agent 执行规范（机器工作流视图）

> **自动生成·规范草案，未代表真实执行。** 唯一规范源：source-data/parent-child-recorder/workflow.json。源资料需在执行当天重新检索；不要将下列 planned 标记为 verified。

**D（目标）**：规划小型可佩戴鱼眼相机（挂脖为候选佩戴方式），尽可能完整记录亲子教学互动；本阶段完成可行性验证与原型方案比较：取景模拟、电脑环境录制链路软件验证、实现路线对比；采购、焊接、烧录与实机制作属于后续阶段。

**受众约束**：希望记录亲子教学过程的家长，不预设拥有相机模组、打印机或电子制作工具。

**禁止误解为目标**：

- 将相机与口喷神器合并制作，或预设二者共用硬件、采购和实施顺序
- 将鱼眼镜头视为已经实现无遗漏记录的证明
- 把电脑环境的模拟或软件验证结果写成目标设备的实测结论（续航、断电、写入、散热仍需设备实测）
- 向公开仓库提交可识别的儿童影像、声音或私人会话
- 在本阶段开展采购、付款、焊接、烧录或外壳制作；这些属于方案确认后的下一阶段

1. 读取当前用户的设备/预算/技能约束；**只问缺少且会改变实际方案的信息**。不要假设用户有 P1S 或 Mac。
2. 自行获取官方上游、工程文件、BOM 和适用的软件版本；对上游每一个关键型号/版本记录来源、时间、可验证范围。
3. 可用工具能读到的页面、CAD/模型、硬件规格和报价，**自己调用工具检查**，不要把“去看源码”转交给用户。工具受限时请求最低限度文件，不编造已检查。
4. 报告每一关的状态：planned / observed / failed / blocked，输出证据位置、影响以及下一步。**模拟 ≠ 实物、读取 ≠ 验收、建议 ≠ 批准付款。**
5. 对付款、首次通电、不可逆烧录/焊接、儿童使用和安全相关动作，要求真实用户决定或现场证据；不绕过安全检查。

### A01 · 整理记录需求与验收边界

- **目的**：形成已确认需求、待设计参数和后续验证方法的草案

- 从已登记的小型可佩戴硬件、鱼眼相机及亲子教学记录目标继续整理，不要求用户重复确认这些需求
- 将佩戴位置、取景覆盖、收音、录制时长、续航、存储和预算保持为待定，说明各项会影响什么设计
- 提出可观察的录制和回看验收方法，仅对新增且会改变方案的取舍请求用户判断
- 保持相机与口喷神器两个独立项目的边界，不生成未经核实的型号、价格或采购结论

- **必须由人完成/提供**：

- **应交付**：设计条件草案（项目页 2026-11-18 轮次）；取景、录制与回看的待验证项清单
- **V 证据**：human-confirmation，草案已发布并区分已确认方向与待定参数；新增关键取舍（分辨率/佩戴高度取舍、试录场景确认）等待发起人判断，当前 planned
- **R 遇阻条件**：缺少参数时记录未知及其影响，继续整理已有需求，不把未定参数写成已确认规格

### A02 · 取景模拟：等距鱼眼投影下的三个候选场景

- **执行者**：agent；**依赖**：无；**状态**：observed
- **目的**：在真实比例几何假设下，比较佩戴高度、镜头下倾与 FOV 对教学场景覆盖的影响
- **Agent 必做**：

- 用显式等距鱼眼投影模型（θ→r 线性，OpenCV fisheye 同族）参数化场景，可重复运行
- 三个候选教学场景（并排读书/面对面小游戏/桌面操作，几何为典型家具假设，均为实验参数）
- 网格比较：佩戴高度 1.35/1.10m × 下倾 0/20/35° × FOV 180/150°，共 36 组
- 量化每个教学目标的视场角 θ、距离与像素宽度，与实验阈值（教学物 100px/手部 80px/面部 60px）判读
- 所有图像与结果标注「模拟预测（非实拍）」；阈值与场景均为实验假设

- **必须由人完成/提供**：

本关不要求你操作。

- **应交付**：generated/framing_sim/results.json（36 组量化结果）；generated/framing_sim/ 各配置示意图与俯视几何图
- **V 证据**：simulation，脚本可重复运行；36 组结果与示意图落盘；结论区分 FOV 覆盖取舍与像素宽度取舍，当前 observed
- **R 遇阻条件**：场景几何与阈值均为假设：若试录显示真实佩戴高度不同，修改参数重跑即可，不据此下硬件结论
- **深入说明**：[详细教程](/projects/parent-child-recorder/01-workflow/)

### A03 · 录制链路软件验证（电脑环境）

- **执行者**：agent；**依赖**：无；**状态**：observed
- **目的**：在本地电脑验证输入→编码→分段→停止→回放最小链路与进程崩溃恢复策略
- **Agent 必做**：

- 用 ffmpeg + 合成信号（1080p30 testsrc2 + 440Hz 正弦）跑通分段录制链路，编码用 VideoToolbox 硬件 H.264
- 正常停止测试 30 分钟：SIGINT 停止后逐段 ffprobe + 全量解码验证
- 崩溃测试：kill -9 中断，分别测 MP4 与 MPEG-TS 分段容器，验证已完成分段可用性
- 记录实测码率、存储占用与 CPU 占用；明确标注「电脑环境的软件验证，非目标设备实测」

- **必须由人完成/提供**：

本关不要求你操作。

- **应交付**：generated/recording_chain_test.py（可重复脚本）；generated/recording_normal_30min.json 与 generated/recording_crash_*.json
- **V 证据**：simulation，脚本可重复运行；正常停止与崩溃结果 JSON 落盘；结论区分软件崩溃与设备断电的边界，当前 observed
- **R 遇阻条件**：崩溃测试只代表软件进程崩溃；设备断电、拔电池、写满等目标设备行为仍须设备实测，不得据此宣称设备级可靠性

### A05 · 分钟级试录：用现成设备验证取景与收音

- **执行者**：shared；**依赖**：A01, A02；**状态**：planned
- **目的**：由成年人在三个候选场景各试录数分钟，核对模拟预测并采集佩戴/收音反馈
- **Agent 必做**：

- 输出试录清单：三个场景（并排读书/面对面小游戏/桌面操作）、每场景 3–5 分钟、核对项与记录表
- 核对项：画面是否覆盖目标内容（对照 A02 预测）、能否听清两人对话、佩戴位置稳定性
- 试录后根据实拍修正 A02 的场景几何参数并重跑模拟

- **必须由人完成/提供**：

- 由成年家庭成员佩戴已有手机（路线乙：挂脖支架或胸前口袋）代替孩子完成试录；孩子不参加本轮
- 按清单逐场景录制并回看，填写核对项；只把佩戴高度、镜头朝向与遮挡感受反馈给 Agent
- 试录素材保留在本地，不上传、不提交仓库

- **应交付**：试录清单与核对表（项目页）；试录后的模拟参数修正
- **V 证据**：physical-observation，三个场景各有一段实拍回看结论：覆盖/收音/佩戴稳定性逐项记录；公开仓库只保留去识别的结论文字，当前 planned
- **R 遇阻条件**：没有成年试录员或手机支架时先不开展；试录素材属私人音视频，仅本地保存
- **深入说明**：[详细教程](/projects/parent-child-recorder/01-workflow/)

### A06 · 目标设备级验证：续航、存储、断电与佩戴

- **执行者**：human；**依赖**：A04, A05；**状态**：blocked
- **目的**：在选定设备上实测 30 分钟基线的续航、存储、断电行为与佩戴可接受性
- **Agent 必做**：

- 在设备到位后提供逐项测试清单：满电连续录制、写满前的存储余量、录制中强制断电后的文件可用性
- 把实测结果回填项目页并更新路线结论；与电脑软件验证结果对比记录差异

- **必须由人完成/提供**：

- 确认实现路线与预算上限；完成采购（或明确暂缓）
- 按 Agent 提供的清单执行设备级测试；断电/复位类操作仅对新设备做一次并接受数据丢失风险

- **应交付**：设备实测记录（数值 + 条件 + 日期）；路线结论的设备级复核
- **V 证据**：physical-measurement，每项有实测数值、条件与日期；与模拟/软件验证的差异显式记录，当前 blocked
- **R 遇阻条件**：预算未确认、设备未到位前本关保持 blocked；不得用电脑软件验证替代设备实测结论
- **深入说明**：[详细教程](/projects/parent-child-recorder/01-workflow/)

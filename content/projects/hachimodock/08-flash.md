# 第 8 步｜在 Apple silicon Mac 上首次烧录

## 目标

把**与芯片实际修订版匹配**的官方完整镜像写入 ESP32-P4。预计 40–90 分钟。**烧录会覆盖设备数据**：只在新设备或确认恢复出厂时使用完整烧录包；已装好固件的设备优先走官方客户端升级。

## 绝不能跳过的版本判断

- ESP32-P4 silicon **v1** 与 **v3** 完整烧录包不能互刷。
- 开发板的 `-M` 仅表示板卡套件/排针型号，不能推断芯片 silicon 版本。
- 让供货商确认芯片修订版，或者按官方文档的识别方法判断；**判断不了就停在本步骤**。

## 操作

1. 在 [HachimoDock 官方 Release](https://github.com/YizhengWw/HachimoDock/releases/latest) 下载对应 v1 或 v3 的**完整烧录包**。不要只下载 `.bin` 后自己猜 flash offset。
2. 同一个 Release 下载 `SHA256SUMS`，在 Mac 的「终端」中运行：

```bash
python3 --version
# 下载后按真实文件名替换下面的 <文件名>：
shasum -a 256 "<下载的完整烧录包文件名>"
```

对照 SHA256SUMS 中的哈希值，必须一致，才能继续。

3. 确认 Python **3.10+**。解压官方包，查看其真实目录、README 和 Mac 烧录脚本。官方完整包包含烧录工具和分段校验材料，当前基线脚本使用 esptool 5.4.0；**不在这里编造未验证的脚本名称和参数**。
4. 将设备通过 USB 数据线连接 Mac，查询串口变化：

```bash
ls /dev/cu.*
```

先拔线运行一次，插线再运行一次，比较新增设备；串口名称可能随机器、USB 转串口驱动而变化。

5. 按完整烧录包自带操作指引选择正确串口和 v1/v3 包执行脚本。如果要求进入下载模式，参考 [微雪开发板 BOOT/RST 说明](https://docs.waveshare.com/ESP32-P4-WIFI6)。
6. 等到工具**明确报告验证通过**后断开、重连 USB。保留烧录输出的最后成功记录，不上传包含设备标识、路径或个人数据的原始日志。

## 不要做的事

- 不要把 v1 和 v3 的固件、分区表、脚本混用。
- 不要忽略烧录脚本的芯片检测失败提示，强制继续写入。
- 不要在不清楚 flash 分区的情况下使用随意搜索到的 `write_flash` 偏移命令。
- 不要关闭 macOS Gatekeeper 或执行未知来源脚本；先核对官方 Release 与 SHA256。

## 验收

- [ ] 记录真实芯片修订版及佐证。
- [ ] 核对了完整烧录包 SHA256 与官方 `SHA256SUMS`。
- [ ] Mac 识别到合适的串口。
- [ ] 使用**官方包提供的脚本**报告成功。
- [ ] 记录烧录前后固件版本和最终状态。

## 出问题怎么办

**找不到串口**：换一条确知可传数据的 USB 线，检查开发板指示灯和 Mac 的 USB 设备列表；观察插拔前后的 `/dev/cu.*` 差异。**芯片版本不匹配**：先断电，回到供货商版本确认。**屏幕不亮**：先确认烧录完成、DSI/FFC 连接和屏幕型号，不要先假设应用崩溃。

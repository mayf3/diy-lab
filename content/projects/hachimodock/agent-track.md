# HachimoDock 哈基米机｜Agent 执行规范（机器工作流视图）

> **自动生成·规范草案，未代表真实执行。** 唯一规范源：source-data/hachimodock/workflow.json。源资料需在执行当天重新检索；不要将下列 planned 标记为 verified。

**D（目标）**：复刻能通过电脑客户端显示真实 Agent 状态的 HachimoDock 桌面装置。

**受众约束**：没有专业电子基础的公众读者；不预设拥有任何品牌 3D 打印机、Mac 或焊接工具。

**禁止误解为目标**：

- 首台不自研 PCB/驱动
- 不代替实物测试或售后保证
- 不自动付款或绕过供电安全
- 不未经许可再发布上游模型、PCB 与视频

## 启动协议

1. 读取当前用户的设备/预算/技能约束；**只问缺少且会改变实际方案的信息**。不要假设用户有 P1S 或 Mac。
2. 自行获取官方上游、工程文件、BOM 和适用的软件版本；对上游每一个关键型号/版本记录来源、时间、可验证范围。
3. 可用工具能读到的页面、CAD/模型、硬件规格和报价，**自己调用工具检查**，不要把“去看源码”转交给用户。工具受限时请求最低限度文件，不编造已检查。
4. 报告每一关的状态：planned / observed / failed / blocked，输出证据位置、影响以及下一步。**模拟 ≠ 实物、读取 ≠ 验收、建议 ≠ 批准付款。**
5. 对付款、首次通电、不可逆烧录/焊接、儿童使用和安全相关动作，要求真实用户决定或现场证据；不绕过安全检查。

## A/V/R（动作、证据、依赖与阻断）

### A01 · 确定制作目标和现有资源

- **执行者**：shared；**依赖**：无；**状态**：planned
- **目的**：选好电脑与打印/焊接路径；先不购物
- **Agent 必做**：

- 仅询问电脑系统、打印资源、焊接条件、预算上限、是否允许供应商联系；未知保留 unknown
- 依据选项列出自有打印、借用、代打印分支和本次最低额外购买需求
- 明确本阶段所有采购、软件烧录和通电都未执行

- **必须由人完成/提供**：

- 回答电脑系统、打印机/代打印计划、是否有焊接工具、预算；不懂型号可拍设备铭牌

- **应交付**：资源路径记录；预算约束
- **V 证据**：human-confirmation，路径、预算、未知项都有明确记录；不要求已有 P1S/Mac，当前 planned
- **R 遇阻条件**：信息不全时使用待确认路线，不阻塞后续公开资料检索
- **深入说明**：[详细教程](/projects/hachimodock/01-start/)

### A02 · Agent 读取官方 GitHub、立创和版本记录

- **执行者**：agent；**依赖**：A01；**状态**：planned
- **目的**：收集正确的上游资源，不让新手自己逐页查阅
- **Agent 必做**：

- 用可用的 GitHub/网页工具读取 HachimoDock README、Releases、当前 license，记录具体链接、检查日期和版本
- 读取 OSHWHub 工程的 PCB_V1.2、SCH_V1.2、BOM、两份 STEP、装配视频的实际获取方式；**不复制未获再发布许可的内容到公开仓库**
- 读取微雪板卡文档并列出已知芯片修订、接口与用户环境的约束，列明哪些文档须登录才可下载

- **必须由人完成/提供**：

- 若受登录或附件权限限制，向 Agent 提供自己合法获得的文件/页面截图，不需要自己判断技术内容

- **应交付**：来源与版本核对表（链接/日期/工程标识）；还未取得的上游文件清单
- **V 证据**：public-source，所有结论可指向官方证据；受限下载如实标 unresolved，当前 planned
- **R 遇阻条件**：官方链接过期或无法访问就标无法读取；不得用未经验证的第三方镜像替代
- **深入说明**：[详细教程](/projects/hachimodock/02-sources/)

### A03 · Agent 做四项兼容性核验

- **执行者**：agent；**依赖**：A02；**状态**：planned
- **目的**：先确认能买对主控、屏幕、PCB、轴体
- **Agent 必做**：

- 从已公开工程和版次说明构建主控 silicon v1/v3—官方固件构建兼容矩阵；M/已焊排针不代表 v3
- 核对屏幕 MIPI-DSI、实际屏幕模组、22P 0.5mm FFC 的触点/长度/驱动；只凭分辨率不判通过
- 核对 PCB_V1.2 与 SCH_V1.2 的 SW1-3 KEY-TH_CPG135001D0X / C400229、排母、摇杆的封装；历史 BOX 文案与 BOM 的差异不能直接判全部问题已解决
- 把公开资料无法确认的具体 SKU/供货批次/外壳配合留 HOLD，写清最低补证信息

- **必须由人完成/提供**：

- 若 Agent 找不到非公开屏幕规格或芯片批次，由人代转发向卖家的精确问题和答复；不要求人自己验证封装

- **应交付**：兼容矩阵与 HOLD 阻塞项；缺证据要问的问题
- **V 证据**：public-source，每个兼容结论有型号、版本、来源及证据等级；尚不能确定的不得 PASS，当前 planned
- **R 遇阻条件**：任一关键型号或接口冲突，停止采购对应批次并升级到原作者/供应商的实证
- **深入说明**：[详细教程](/projects/hachimodock/purchase-plan/)

### A04 · Agent 模拟装配并决定打印路线

- **执行者**：shared；**依赖**：A02, A01；**状态**：planned
- **目的**：在付款之前识别结构冲突与打印方案
- **Agent 必做**：

- 根据官方 STEP、PCB 3D、屏幕/主控尺寸图做几何检查：孔位、按键高度、FFC 弯折、USB 开口、螺孔
- 对自有打印机：根据真实型号、喷嘴、材料使用对应切片器，提供朝向/支撑/耗材/时间的**模拟结果**；不能沿用 P1S 参数当通用方案
- 对没有打印机：生成可交给合法代打印服务的规格单（文件、材料、强度用途、关键孔尺寸、是否需要试件、预计数量），收集含运费报价
- 所有没有真实 CAD 输入或尺寸图的项标 UNKNOWN，不把模拟当作实物配合通过

- **必须由人完成/提供**：

- 选择自己的打印或代打印路径；如模型只能登录下载，提供源文件给有权限的 Agent；暂无机器也能先做模拟

- **应交付**：几何碰撞/公差清单；打印或代打印方案与试件计划
- **V 证据**：simulation，软件/模型/版本/假设均记录；所有物理卡口待实物干配，当前 planned
- **R 遇阻条件**：缺 STEP/尺寸图不能宣称“无碰撞”；先询问文件或向供应商索取尺寸
- **深入说明**：[详细教程](/projects/hachimodock/04-simulation/)

### A05 · Agent 形成可采购的 BOM 和真实到手预算

- **执行者**：agent；**依赖**：A03, A04；**状态**：planned
- **目的**：让人拿到精确购物单而不是规格模糊的商品名
- **Agent 必做**：

- 根据 source-data/hachimodock/bom.csv、blockers.csv 更新各项 SKU、替代与数量
- 查执行当天真实在售渠道和报价，记录商品页链接、售卖地区、发布时间/读取日、价格、运费、PCB 打样最小数量和代打印费用
- 核算一次性工具成本与可复用材料；将官方历史参考价与当日实际报价分列
- 若仍有 HOLD，输出无法下单的清单，并指出可先采购的低风险通用件

- **必须由人完成/提供**：

本关不要求你操作。

- **应交付**：可追溯到 SKU 的购物单；含运费预算及待确认项
- **V 证据**：public-source，型号与精确报价/运费明确，关键 HOLD 未被默默放行；无报价不声称预算已闭环，当前 planned
- **R 遇阻条件**：渠道无法读取实价就请求人提供购物车截图，由 Agent 计算；不把搜索摘要当实时成交价
- **深入说明**：[详细教程](/projects/hachimodock/03-bom/)

### A06 · 采购授权门禁：人确认是否下单

- **执行者**：human；**依赖**：A05；**状态**：planned
- **目的**：避免错买和未经授权的支付
- **Agent 必做**：

- 给出分批采购选择：必要核心件、标准五金、工具与打印路线；逐项标明 PASS/HOLD/UNKNOWN 和总价
- 出示清单与风险，但不因为是公开 BOM 就自动放行付款

- **必须由人完成/提供**：

- 对精确 SKU、数量、含运费总价作最后决定；明确授权后才付款/安排代打印/打样

- **应交付**：用户购买决定及具体 SKU 批次
- **V 证据**：human-approval，有明确同意和准确商品、价格、渠道；关键 HOLD 不允许靠推测直接购买，当前 planned
- **R 遇阻条件**：仍有决定性 HOLD 或预算超标时，不付款，返回 Agent 检查或换方案
- **深入说明**：[详细教程](/projects/hachimodock/purchase-plan/)

### A07 · 完成采购、PCB 打样或代打印订单

- **执行者**：shared；**依赖**：A06；**状态**：planned
- **目的**：正确获得零件，不擅自更改官方电路
- **Agent 必做**：

- 按已经授权的精确型号生成商家/工厂下单参数（PCB 基于上游指定工程，避免误点自动同步网表）
- 登记订单到货时间、SKU 与预计数量，不要求公开姓名/地址/付款截图

- **必须由人完成/提供**：

- 自行完成付款或另行显式授权支持的交易工具；收货核对包装与料号，仅向 Agent 分享去隐私的规格照片

- **应交付**：采购台账、实收料号与缺件表
- **V 证据**：physical-observation，实收型号与授权清单一致；发货不等于到货验证，当前 planned
- **R 遇阻条件**：收到不匹配型号立即停止对应安装并联系商家，不带电试错
- **深入说明**：[详细教程](/projects/hachimodock/05-pcb/)

### A08 · 打印外壳或验收代打印件

- **执行者**：shared；**依赖**：A07, A04；**状态**：planned
- **目的**：得到可实际干配的外壳
- **Agent 必做**：

- 按真实设备/代打印商能力准备专用切片或服务验收表，优先试验螺孔、屏幕和按键局部件
- 看到用户照片与卡尺尺寸后对照 CAD 建立误差表；Agent 只能辅助解释物理观察

- **必须由人完成/提供**：

- 有打印机则按机型安全流程打印，没打印机则收代打印件；用卡尺/实物检查屏幕、按键、USB 孔、PCB 干配；上传去隐私的照片或读数

- **应交付**：试件和尺寸记录；最终外壳与打印消耗
- **V 证据**：physical-measurement，由实际干配/尺寸测量证明；数字切片不能等同通过，当前 planned
- **R 遇阻条件**：配合不通过时只调整明确失败位置，先打小试件而非盲目重打整件
- **深入说明**：[详细教程](/projects/hachimodock/06-print/)

### A09 · 焊接 PCB 并进行断电检查

- **执行者**：shared；**依赖**：A07；**状态**：planned
- **目的**：避免引脚错焊和通电短路
- **Agent 必做**：

- 提供对应 PCB_V1.2 的元件位置、焊接方向和万用表测量位置；照片不足时明确要求更清晰细节
- 将检查结果分为看图判断与人实际测量，不凭照片说电路绝对安全

- **必须由人完成/提供**：

- 如果不具备焊接经验，先练习或找有能力的协助者；断电插入器件并焊接，用万用表确认关键点无意外短路；发现异常立即停止

- **应交付**：焊点照片、断电检查记录
- **V 证据**：physical-measurement，经过实际测量而非 Agent 看图推测；不确定时不通电，当前 planned
- **R 遇阻条件**：短路、冒烟、发烫或型号冲突就断电停止，不能继续刷固件验证
- **深入说明**：[详细教程](/projects/hachimodock/07-solder/)

### A10 · Agent 准备匹配固件，人确认写入

- **执行者**：shared；**依赖**：A09, A03；**状态**：planned
- **目的**：按实际 ESP32-P4 芯片修订烧录正确固件
- **Agent 必做**：

- 按执行当天上游 Release 和实际芯片检测结果选 v1/v3 固件与官方烧录脚本
- 校验官方校验和、识别机器平台与串口，提出明确命令及其写入影响
- 不要跳过上游的芯片版次检查、硬编码 flash offset 或混刷不同包

- **必须由人完成/提供**：

- 连上 USB，按提示操作 BOOT/RST；在了解会覆盖设备数据后授权执行烧录；记录终端成功/失败输出（去除设备 ID）

- **应交付**：实际芯片版次证据；固件 SHA-256 与烧录日志
- **V 证据**：device-log，官方工具报告烧录并校验成功；脚本准备好不等于烧录完成，当前 planned
- **R 遇阻条件**：芯片版本不清、脚本签名/来源不明、烧录报错立即停止写入；先读真实错误再修
- **深入说明**：[详细教程](/projects/hachimodock/08-flash/)

- **应交付**：连接与交互证据；系统/客户端/固件版本
- **V 证据**：physical-observation，实机能显示一次真实 Agent 状态变化，按键和音频通过相应测试，当前 planned
- **R 遇阻条件**：系统不受官方支持、USB 不识别或屏幕不亮时不编造兼容结论，回退到官方支持条件

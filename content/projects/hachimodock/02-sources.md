# 第 2 步｜下载资料与锁定版本

## 目标

把所有上游资料定位到**权威原始位置**，明确版本、版权与使用边界，不因下载错误文件导致 PCB、固件或外壳不匹配。预计 20–40 分钟。

## 操作

1. 从 [立创硬件项目](https://oshwhub.com/eda_gqvzlprk/project_cnbmkbjc) 找到 `PCB_V1.2` 和 BOM；在 EDA 中查看，不要点击“更新网表”后直接打板。
2. 在页面 **3D模型** 区域下载：`桌搭-整机外壳3d打印版.STEP` 与 `屏幕lens 3d打印版.STEP`。
3. 在同页面 **附件** 区域找到官方完整装配教程 `.mp4`，放到电脑本地 `originals/`；记下实际文件名、下载时间和来源。
4. 打开 [官方 GitHub README](https://github.com/YizhengWw/HachimoDock) 阅读“新设备或恢复出厂”“快速开始”。
5. 打开 [最新 Releases](https://github.com/YizhengWw/HachimoDock/releases/latest)，记录客户端版本、固件版本，确认有 **ESP32-P4 v1 / v3** 两类不同的完整包。
6. 下载 Release 附件后，和同一 Release 的 `SHA256SUMS` 对照，不要在不同日期混用脚本与固件镜像。
7. 打开 [微雪开发板文档](https://docs.waveshare.com/ESP32-P4-WIFI6)，确认开发板型号及板载 MIPI-DSI、音频接口。

## 已核实的资料基线（2026-11-06）

| 项目 | 已知情况 | 后续必须核实的内容 |
| --- | --- | --- |
| macOS 客户端 | 0.1.201，Apple silicon（同日早间为 0.1.199，已复核漂移） | 下载当天检查 Release 是否更新 |
| 设备固件 | `0.7.103-p4-r181`（同日早间为 r179） | 按开发板实际 v1/v3 选择 |
| PCB | 官方提供 `PCB_V1.2` | 网表/封装冲突是否影响当批板 |
| 外壳 | 官方提供两份 STEP 文件 | 首轮实际打印能否与实物合拢 |
| 屏幕 | 2.8 英寸，480×640，MIPI-DSI，22P FFC | FFC 方向/长度、屏幕外形尺寸、驱动 |
| 主控 | ESP32-P4-WIFI6 或 WIFI6-M | 实际 silicon 修订 + 是否焊排针；收货后用 `esptool chip_id` 实读验证 |

以上基线同步登记在可下载的[来源登记表](/downloads/hachimodock-sources.csv)（含每个来源的精确网址、版本标识和查看日期）。距上次核对超过 90 天时 `scripts/check.py` 会提示“复核版本是否漂移”；届时先重开 Releases 页面确认客户端/固件是否更新，再更新登记表日期，不要凭记忆标“仍是最新”。

## 为什么不能直接复制上游文件到自己的仓库？

本站发布的是**自己写的复刻步骤和自己的实测记录**，并不自动获得上游 PCB、三维结构、官方视频及宠物素材的再发布权。GitHub 项目当前为非商业范围许可，立创硬件页面也明确有限制；硬件页面的旧 GPL 标注不能覆盖所有材料。需要共享原件时请链接作者的官方位置，不把上游素材复制进这个仓库。参见 [使用与版权说明](/guide/legal/)。

## 验收

- [ ] 已能打开 GitHub、Releases、OSHWHub、微雪文档四个权威入口。
- [ ] 已找到两个 STEP 文件与装配视频附件的下载入口。
- [ ] 已记录实际下载版本、文件名、日期和校验结果。
- [ ] 已确认下载 v1/v3 固件前需要知道**芯片实际修订版**。

## 出问题怎么办

若原始页面链接变更，可从作者 GitHub README 重新进入硬件页面。某些附件需要登录立创后下载；不要用无来源的文件替代。若网页显示的版本与本指南不同，按新版原文记录差异，并先检查兼容性再继续。

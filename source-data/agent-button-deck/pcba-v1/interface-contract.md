源码依据：F 6、15、30–36、49–53 行。固件调用 `pinMode(..., INPUT_PULLUP)`，利用 MCU 内部上拉；**现有源码没有要求外置上拉电阻，也没有规定其阻值**。首版应保持常开、按下接地、低电平有效；如评审决定增加外部上拉、RC 或保护器件，须另有电气依据、准确料号及复测，不能把它们写成原软件已验证的元件。

官方资料依据：[Espressif ESP32-S3-DevKitC-1 v1.1 用户指南](https://docs.espressif.com/projects/esp-dev-kits/en/latest/esp32s3/esp32-s3-devkitc-1/user_guide_v1.1.html#header-block) 的 J1 表；本次查看为 2026-11-26。其 J1 第 22 脚及 J3 第 1/21/22 脚标为地。**这些位置只属于该官方板参考；采购主板未锁定，不能直接当成最终载板焊盘编号。** 必须逐脚建立“模块引脚—插座焊盘—PCB 网络”映射，检查从板顶/板底观察时的镜像和 Pin 1。

四个开关共用 GND，但四个信号网络相互独立。GPIO 不接 5 V。若选择四脚轻触开关，先从准确开关手册核对常通的两组脚，再用断电导通检查验证；不能靠封装长相判断触点。对应原阻断 BD1、BD2（K 2–3 行）。

### 2.2 去抖与边沿行为

| 行为 | `5654c5d` 实际实现 | 对验收的含义 |
| --- | --- | --- |
| 去抖 | `kDebounceMs = 35`；原始电平每次变化重新计时，稳定达到 35 ms 后更新状态 | 很短的按压可能被过滤；不能承诺任意速度都逐次识别 |
| 采样 | 轮询四路 GPIO，每轮 `delay(2)` | 2 ms 是代码中的延时，不是已测得的完整响应时延 |
| 按下 | 稳定状态变为 LOW 时调用 `emitPress(i)` | 每次经过去抖的按下发一行 |
| 松开/长按 | 松开只更新状态，没有 release 事件；持续 LOW 不反复发送 | 按住 2 秒应只发一次；再次按下前要有被识别的松开 |
| 开机时按住 | `setup()` 把读到的当前电平同时作为原始和稳定初态 | 上电已经按住的键不会补发 press；需松开再按 |
| 多键 | 四路状态独立，轮询顺序 K1→K4 | 可分别报告多路按下；没有组合键语义，也没有可用于排序物理先后的时间戳 |

依据：F 17–21、29–36、40–57 行。没有硬件/示波器日志证明触点抖动、最短操作间隔或整机时延已达标。

## 4. 串口与电脑端协议

### 4.1 设备发出的真实字段

```json
{"v":1,"event":"press","key":"K1"}
```

F 23–26 行按上述字段和顺序写出内容，再调用 `Serial.println` 结束一行；K2–K4 仅替换 `key`。电脑端以 `\n` 作为读取分隔符。H 125–149 行要求事件是 JSON 对象，**字段集合恰好为 `v`、`event`、`key`**：`v` 必须是整数 1（布尔值不算），`event` 必须是 `press`，`key` 由 `_key_ok` 检查。

- 设备实际仅发 K1–K4；host 接受 K1–K64 是解析上限，不能据此声称有 64 键硬件（F 15–16；H 37–40）。
- 输入须为 UTF-8，单次输入最多 512 字节；串口 `read_until(b"\n", size=513)`，读取超时为 1 秒。非法 UTF-8、额外字段、错误版本、非 press 或非法键值被忽略（H 34、125–149、260–265）。
- 原协议没有序号、时间戳、校验字段、设备身份、设备到 host 的确认机制、host 到设备的指令或设备状态灯控制。不要向现有事件中直接加字段，严格解析器会拒绝。
- host 当前按一次读取直接解析，未实现跨超时片段重组；断线异常退出后也没有自动重新枚举/重连循环。USB 重插恢复不能写成已有自动功能（H 258–271）。

### 4.2 映射留在 Mac

H 80–118 行要求配置顶层只有 `schema_version: 1` 和 `routes`，支持 1–64 个映射；未知按键没有动作。以下是 M 中的**示例值，不是用户已经选择或验证的动作**：

| 示例键 | `type` | 该类型准确配置字段 | 示例内容 |
| --- | --- | --- | --- |
| K1 | `open_app` | `type`、`bundle_id` | `com.apple.Notes` |
| K2 | `open_url` | `type`、`url` | `https://example.com` |
| K3 | `shortcut` | `type`、`name` | `AI Lab Capture` |
| K4 | `agent_event` | `type`、`route_id`、`endpoint` | `research` → `http://127.0.0.1:8765/button` |

默认只打印 `[DRY RUN]`；启用实际动作需要启动参数 `--enable-actions`（H 191–213、225–251）。应用、网址和 Shortcut 的执行路径面向 macOS；串口数据本身不能提供命令参数。配置、私有会话地址和凭据不放入 MCU 或公开项目资料。

`agent_event` 会由 host 另外组成 HTTP POST JSON：

```json
{"source":"agent-button-deck","v":1,"event":"press","key":"K4","route_id":"research"}
```

这不是串口包。H 60–77、159–175 行将 endpoint 限定为带显式端口的 `http://127.0.0.1` 和受限路径；禁止重定向，超时 3 秒，检查 HTTP 2xx。**该源码没有实现 adapter，也不核对目标 Agent 会话的实际投递回执**；HTTP 2xx 只能证明当前代码接受了 adapter 的响应。BD5 仍开着，不能把“打开网页”“localhost POST 被接受”写成“已经给指定会话发送消息”。

动作同步执行，普通本地动作超时上限 30 秒（H 188 行）；因此整机连续按键吞吐与慢动作期间的积压行为也要实测，不能用 35 ms 去抖值替代端到端性能。

## 6. 设计与机械检查输入

### 电气检查计划

1. 锁定主板后建立逐脚映射，确认 K1–K4 真正到 GPIO4–7、四路互不短接、所有需要的地连通；不用的插座脚按原理图明确处理，不把 5 V/3.3 V 与按钮网络混接。
2. 断电测按钮未按开路、按下导通，核对四脚开关的内部公共脚；再检查电源对地短路及排针错位/反插。
3. 核对实际板载 USB-UART 和电源路径，保留其正常下载、启动和复位条件。检查载板是否意外加载 UART/BOOT/EN 或影响原有功能；GPIO4–7 不输入 5 V。
4. 在原生 EDA 对选定版本运行并读回原理图检查、PCB DRC、未连接网络与关键网络连通性；逐条解释真实例外，记录工具/工程版本及报告。当前没有上述检查结果。
5. 最终装配件测量供电电压、运行电流、异常复位/发热以及按键输入电平，结果附测试条件。数值限值应来自最终器件/电源设计；本文不填通用猜测值。

### 机械检查计划

先取得主板和按钮/插座的原厂尺寸图，并核对实际件。板框、孔位、键间距、板厚、插座高度和外壳尺寸均未冻结；不能从图片或默认模块模型推定最终尺寸。依据同版 PCB/STEP 与实际包络检查：

- 两排插座的排距/孔距/方向和板底突出焊脚，插好后是否稳定，四键按压载荷是否由固定结构承担。
- USB-to-UART 口的朝向、插头外形、插拔手指空间、线缆弯曲空间；区分旁边的原生 USB 口。
- 按键帽与开关轴线、自由高度、行程、外壳孔位和装壳后的回弹，避免壳体持续压住某键。
- 开发板、载板、螺柱/螺丝、外壳之间的电气及机械间隙；USB 插拔时板件不松动。
- BOOT/RESET、烧录与维修的可达性；板载天线区域的实际模块净空要求，后续无线功能需要另验收。
- 首次打印先验证端口/按键/螺柱配合小样，再定正式外壳；未实测时不宣称“可装配”。

# Space Buddy Deck R1 · M1–M4 模型与跨版本一致性约束

**状态：模型文档（G0/G1 阶段）。M4 视觉质量不在数学可证范围内，保留人工评审。**
方法与证据分层遵循 mayf3/primitives `67212e4` 的 MODEL_CENTERED_DEVELOPMENT v0.1.0
（需求→模型→Lean→实现映射→真实验收，三层证据不可互相替代）。

## 版本约定（跨模型一致性约束 · 本项目最重要的一条）

R1 的每个对外产物（PCB、CAD、固件、BOM）必须携带同一个 **R1 版本四元组**：

```text
R1.<pcb_rev>.<cad_rev>.<fw_rev>.<bom_rev>   例：R1.A.1.draft.3
```

一致性约束（未来 Lean 优先验证的稳定命题）：

1. **四元组一致**：任一对外产物声称的版本号，四段必须全部存在且互相引用。
2. **变更传播**：任一段变更 → 整个版本号递增，并且其余三段必须显式声明"未变"或同步更新。
3. **禁止部分声明**：只有两段的版本声明无效（例如"PCB rev B"而不说固件/外壳适配版本）。
4. **制造冻结的条件**：四元组全部为已冻结整数版本且通过 G6 检查。

这条约束的现实意义：PCB、外壳、固件、BOM 由不同工具（EDA/CAD/Arduino/表格）维护，
历史上最常见的失败就是"板子改了、壳没跟上"或"固件引脚和丝印不一致"。模型先把
"必须成套发布"表达出来，实现用目录命名与 manifest 检查落实。

## M1 电气连接模型

**对象**：键 K1–K4；MCU 引脚 GPIO4–7；网络 NET_K1–NET_K4；GND；USB OTG 口；USB UART 口。

**连接关系（与固件唯一映射）**：

```text
K1.触点对 → NET_K1 → GPIO4（J1.4）
K2.触点对 → NET_K2 → GPIO5（J1.5）
K3.触点对 → NET_K3 → GPIO6（J1.6）
K4.触点对 → NET_K4 → GPIO7（J1.7）
四路共用 GND → J1.22 / J3.1 / J3.21 / J3.22
```

**性质（P1 电气）**：
- P1.1 映射唯一：每个 K_i 恰好映射到一个 GPIO_i，无共享、无交叉。
- P1.2 无混接：任何键网络不接触 5V/3V3/EN/BOOT/UART 线。
- P1.3 GND 连通：四路共地且与插座地贯通。
- P1.4 接口分离：OTG 口承担 HID；UART 口仅烧录/维护，两口互不承载对方功能。

**实现对应**：原理图网络表 ↔ 上表；固件 `kPins[] = {4,5,6,7}` ↔ 上表；
PCB 布线检查（DRC+连通性）↔ P1.1–P1.3。验证方式：EDA 检查报告 + 固件源码核对（非 Lean）。

## M2 机械结构模型

**对象**：载板（PCB）、四键开关（机构待 G1 定档）、键帽 ×4、插座、外壳上盖/下盖、
USB 开孔、螺柱、脚垫。

**约束（待 G1 尺寸冻结后量化）**：
- 键帽按压垂直行程内不倾斜、不卡滞（导向或轴杆自导向）。
- 按压载荷由结构（螺柱/插座焊脚/导向柱）承担，不悬空。
- 双 USB 口开孔与插头外形匹配，插拔不松脱板件。
- 壁厚 ≥2mm，印刷公差 ±0.2–0.4mm，运动配合留 0.3–0.5mm 间隙。
- 板载天线区净空：金属件远离模组天线端。

**检查方式**：CAD 自动干涉检查 + 首版试装小样（G3/G5）。**不用 Lean 做几何**。

## M3 制造状态模型

```text
Designed → Checked → Manufacturable → Ordered
        → Manufactured → Assembled → Accepted
```

| 状态 | 进入条件（必须全部成立） | 证据 |
| --- | --- | --- |
| Designed | 原理图+PCB 存在且保存落盘 | 原生工程文件 |
| Checked | 原理图检查、PCB DRC、未连网络清零或逐条处置 | 检查报告 |
| Manufacturable | Gerber/BOM/CPL/STEP 齐全，代焊范围确认，BOM 元件在售 | 制造包+工厂确认 |
| Ordered | 发起人本人批准并付款 | 订单回执（不含账号） |
| Manufactured | 工厂交付实物 | 到货照片+板号 |
| Assembled | 开发板插接、烧录、按键装帽完成 | 组装记录 |
| Accepted | 四键各 10 次无错号、装壳可操作、USB 重插恢复 | 实测记录 |

**性质（P3 状态机）**：
- P3.1 只能沿箭头方向前进，不得跳态（如未 Checked 不得 Manufacturable）。
- P3.2 回退（设计变更）必须显式回到 Designed 并使下游状态失效。
- P3.3 Ordered 之后的回退不影响已付事实的记录，但产品回到 Assembled 前不得 Accepted。

**实现对应**：工作台 product_ready/冻结三态与 catalog 阶段字段；验证方式=工作台测试 + 人工核对。

## M4 视觉设计模型

**对象**：2×2 键帽（位置/尺寸/颜色/图案）、宇航员头像、舷窗、星星、底座、丝印。

**已冻结（G0）**：布局关系、颜色映射（四键四色）、装饰元素清单、主题风格。
**未冻结**：一切毫米级尺寸。

**验证方式**：M4 审美与"像不像太空舱"**保留人工视觉评审**（发起人 G0 确认即为其评审记录）；
数学模型只表达结构关系（键中心间距相等、四色互异、图案与键位一一对应），
这些结构条件可以检查，但"好看"本身不由 Lean 证明——避免代理指标冒充真实目标。

## Lean 优先级（不制造无价值任务）

1. **优先**：M3 状态机合法性（不允许跳态/回退显式化）——稳定、后果重要、可机器检查。
2. **优先**：跨模型版本一致性约束（四元组一致与变更传播）——跨 EDA/CAD/固件/BOM 的协议性质。
3. **可选**：M1 映射唯一性的形式化（当前规模小，检查表+EDA 报告已足够；若载板布线复杂化再升级）。
4. **不做**：M2 几何、M4 审美——分别交给 CAD 检查与人工评审。
